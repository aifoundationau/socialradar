We are setting up Stripe Payments (Sandbox / Live) for this web app. Follow these exact architectural rules without exception:

### 1. CORE BUSINESS & NATIVE STRIPE TAX INVARIANTS
0. **Stripe Dashboard Tax Settings:**
   - In **Stripe Dashboard → Settings → Tax**:
     - **Use automatic tax calculation:** **Yes**
     - **Include tax in prices:** **No** (`tax_behavior: "exclusive"`)
1. **Default Currency:**
   - All checkouts, subscriptions, and line items MUST strictly use Australian Dollars (`currency: "aud"`).
   - The base price is always the exact price configured in the Admin Panel / database (e.g. 10 Tokens = `$10.00 AUD`, Monthly Search Subscription = `$700.00 AUD/mo`).
2. **Automatic Stripe Tax (`automatic_tax: { enabled: true }`):**
   - Enable `automatic_tax: { enabled: true }` on both `mode: "payment"` and `mode: "subscription"`.
   - Stripe Checkout automatically detects the customer's country, state, and postal code directly on the hosted payment form.
   - You do NOT need to geolocate or pass the customer's country in advance.
   - Tax behavior is set to `tax_behavior: "exclusive"` on line item `price_data`.
   - **Australian buyers:** Stripe adds 10% Australian GST on top of the base price (e.g., $50.00 AUD + $5.00 GST = $55.00 AUD total; $700.00 AUD/mo + $70.00 GST = $770.00 AUD/mo).
   - **International buyers:** Stripe automatically charges $0 tax and collects the exact base AUD price.
3. **Zero Manual Tax Rates (`txr_...`):**
   - NEVER create, fetch, cache, or pass manual `tax_rates` (`txr_...` / `ensureAuGstTaxRateId()`).
   - Stripe Tax computes all jurisdiction rules and calculations automatically.
4. **Dynamic Products & Zero Pre-created Products:**
   - Because prices and tiers can change in the Admin Panel at any time, NEVER hardcode or pre-create `prod_...` or `price_...` objects in Stripe.
   - Always pass inline `price_data` + `product_data` in `stripe.checkout.sessions.create(...)`.
5. **Official Tax Invoices:**
   - One-time purchases (`mode: "payment"`) must include:
     ```ts
     invoice_creation: {
       enabled: true,
       invoice_data: { metadata },
     }
     ```
   - Monthly subscriptions (`mode: "subscription"`) automatically create an invoice (`in_...`).
   - Both produce downloadable PDF tax invoices separating Ex-GST Subtotal, Tax/GST, and Total.

### 2. SERVER-SIDE STRIPE HELPER (`src/lib/stripe.ts`)

Implement `buildCheckoutParams()` and `fulfillCheckoutSession()` using this clean pattern:

```ts
import "server-only";
import Stripe from "stripe";

let client: Stripe | null = null;

export function getStripe(): Stripe {
  if (!client) {
    const key = process.env.STRIPE_SECRET_KEY;
    if (!key) throw new Error("STRIPE_SECRET_KEY is not set");
    client = new Stripe(key);
  }
  return client;
}

export function buildCheckoutParams(opts: {
  uid: string;
  email: string;
  stripeCustomerId?: string;
  pack: { id: string; tokens: number; priceCents: number };
  isSubscription: boolean;
  productName: string;
  appUrl: string;
}): Stripe.Checkout.SessionCreateParams {
  const { uid, email, stripeCustomerId, pack, isSubscription, productName, appUrl } = opts;
  const tokensFormatted = pack.tokens.toLocaleString("en-AU");
  const priceFormatted = (pack.priceCents / 100).toFixed(2);

  const metadata: Record<string, string> = {
    uid,
    packId: pack.id,
    tokens: String(pack.tokens),
  };

  if (isSubscription) {
    return {
      mode: "subscription",
      client_reference_id: uid,
      metadata,
      subscription_data: { metadata },
      automatic_tax: { enabled: true },
      ...(stripeCustomerId
        ? { customer: stripeCustomerId }
        : email
          ? { customer_email: email }
          : {}),
      line_items: [
        {
          quantity: 1,
          price_data: {
            currency: "aud",
            tax_behavior: "exclusive",
            unit_amount: pack.priceCents,
            recurring: { interval: "month" },
            product_data: {
              name: productName,
              description: `Allocate ${tokensFormatted} Searches / Month ($${priceFormatted} AUD / mo)`,
            },
          },
        },
      ],
      success_url: `${appUrl}/wallet?checkout=success&session_id={CHECKOUT_SESSION_ID}`,
      cancel_url: `${appUrl}/wallet?checkout=cancelled`,
    };
  }

  return {
    mode: "payment",
    invoice_creation: {
      enabled: true,
      invoice_data: { metadata },
    },
    automatic_tax: { enabled: true },
    client_reference_id: uid,
    metadata,
    payment_intent_data: {
      description: `${tokensFormatted} Tokens ($${priceFormatted} AUD)`,
      metadata,
    },
    ...(stripeCustomerId
      ? { customer: stripeCustomerId }
      : { customer_creation: "always", ...(email ? { customer_email: email } : {}) }),
    line_items: [
      {
        quantity: 1,
        price_data: {
          currency: "aud",
          tax_behavior: "exclusive",
          unit_amount: pack.priceCents,
          product_data: {
            name: productName,
            description: `${tokensFormatted} tokens ($${priceFormatted} AUD)`,
          },
        },
      },
    ],
    success_url: `${appUrl}/wallet?checkout=success&session_id={CHECKOUT_SESSION_ID}`,
    cancel_url: `${appUrl}/wallet?checkout=cancelled`,
  };
}
```

### 3. CHECKOUT ROUTE & STALE CUSTOMER AUTO-RETRY (`POST /api/wallet/checkout`)
1. Derive `appUrl` dynamically from `new URL(req.url).origin || process.env.APP_URL` so Stripe redirects back to the exact local port or production domain the user started from.
2. If `user.stripeCustomerId` is stored in Firestore from an older Stripe account or test environment and `stripe.checkout.sessions.create` throws `No such customer`, catch the error and immediately retry with `stripeCustomerId: ""` so a fresh Stripe Customer is created automatically without failing checkout.

### 4. DUAL PAYMENT CONFIRMATION & IDEMPOTENT TOKEN DISTRIBUTION
Never rely solely on webhooks during local development or if a webhook is delayed:
1. **Shared Idempotent Fulfillment (`fulfillCheckoutSession(session)`):**
   - Verifies `(session.mode === "payment" || session.mode === "subscription") && session.payment_status === "paid"`.
   - Verifies `session.metadata.uid === session.client_reference_id`.
   - Reads `session.amount_total`, `session.total_details?.amount_tax ?? 0`, and `session.amount_subtotal`.
   - Credits `Number(session.metadata.tokens)` to `users/{uid}.tokenBalance` inside an atomic database transaction using `txId = session.id`.
   - If transaction already exists, returns `{ replayed: true }` without crediting twice.
   - If `session.mode === "subscription"`, also records active subscription details.
2. **Direct Return Confirmation Endpoint (`POST /api/wallet/confirm`):**
   - When the browser returns to `/wallet?checkout=success&session_id=cs_test_...`, the frontend immediately calls `POST /api/wallet/confirm` with `{ sessionId }`.
   - The server calls `await getStripe().checkout.sessions.retrieve(sessionId)`, verifies ownership, and runs `fulfillCheckoutSession(session)`.
   - Tokens and subscriptions are distributed immediately within 1 second.
3. **Stripe Webhook Endpoint (`POST /api/webhooks/stripe`):**
   - Handles `checkout.session.completed` and `checkout.session.async_payment_succeeded` by calling the exact same `fulfillCheckoutSession(session)` (idempotent on `session.id`).
   - Handles `invoice.paid` where `invoice.billing_reason === "subscription_cycle"` (for Month 2+ recurring monthly renewals), crediting the monthly token allowance using `txId = invoice.id`.
   - Handles `customer.subscription.deleted` to set `subscriptionStatus: "canceled"`.
